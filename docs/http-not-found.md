# 静态错误文档导出

前台 HTTP 404 修复由 zrlog-blog-web 负责：使用已有 NotFindPageVO 判断状态，继续渲染主题原有 detail/404 结构，阻止失效文章进入普通页面缓存。共享层只补齐静态抓取对错误文档的处理。

StaticSitePlugin 仅在抓取任务 key 等于 notFindFile() 时，额外接受 404 响应并登记导出文件。仍接受旧 blog 的 200 响应，保持分批升级兼容。普通页面只接受 200；错误文档的 302、500 等不会写入或登记。导出的错误文档不参与链接抓取，路径比较使用带 context path 的任务 key，避免子目录下漏判。

BodySaveResponse 既有三参数构造器的写入与 getCacheFile 语义不变；新增包内构造器指定可额外接受的状态。没有修改 public API、模板 DTO、数据库或 Native 注册。

验证：base 完整测试及新增前缀回归共 480 项均通过；本地 install 通过；下游 blog 使用 JDK 21 完整 verify 通过（130 项测试及既有覆盖率门禁）。BodySaveResponse 覆盖默认拒绝非成功状态、指定错误文档接受 404/旧 200、拒绝 302/500；真实静态抓取覆盖根路径和 /sub 下的错误文档生成与不递归抓取。

线上尚未部署；独立静态托管仍需配置该文件为错误文档，并由托管端返回 404。
